# Lyrics audit, October 3, 2026

The library has 761 entries with synced lyrics, or 42.35%. Fresh lookups found matched timed lyrics for at least 187 more entries. Backfilling them would bring stored coverage to 948 of 1,797 entries, or 52.75%.

This was a read-only audit. No library audio, tags, sidecars, database rows or remote files were changed. App code was not changed.

## Current coverage

The denominator is all 1,797 locally managed audio files, including four retained No longer wanted entries. This counts library entries across albums and singles, rather than deduplicating the same recording across releases.

| Lyrics | Entries | Library share |
| --- | ---: | ---: |
| Synced | 761 | 42.35% |
| Plain, without timestamps | 134 | 7.46% |
| None | 902 | 50.19% |
| Missing synced lyrics, plain plus none | 1,036 | 57.65% |

Every audio file was read through the app's tag reader. The embedded lyrics matched the database for all 1,797 files. All 761 expected `.lrc` sidecars exist, contain nonzero timestamps and match the stored lyrics text. There were no extra sidecars attached to plain or empty entries.

Synced lyrics currently come from Spotify for 527 entries, YouTube Music for 169, and LRCLIB for 65. Plain lyrics come from YouTube Music for 60, Spotify for 56, and LRCLIB for 18. Of the 134 plain entries, 115 are identified as Japanese by the app.

The source rows overlap. Spotify and LRCLIB together cover 69 distinct entries. PetitLyrics supplies another 118 beyond those 69.

The 187 matches comprise 129 entries currently without lyrics and 58 currently carrying only plain lyrics. They represent 18.05% of entries lacking synced lyrics and 10.41% of the whole library. The full [recovery list](lyrics-recoveries-2026-10-03.md) links each entry to its provider records. Exact query variants, source IDs and duration differences are preserved in the JSON evidence.

This is a confirmed minimum of availability. It is not a claim that the remaining 849 entries cannot have timed lyrics. Some searches failed, titles and aliases can still be improved, and additional providers were not exhaustively queried. Metadata and timestamp checks also do not substitute for listening to every imported file and checking its offset.

Examples include East Of Eden's “Breaker”, “I don't say goodbye”, “Don't Look Back” and “Eden” through PetitLyrics; several Sokoninaru album tracks through LRCLIB; and “極限は刹那” through improved Spotify search.

## Spotify calls and matching

The configured Spotify lyrics API is operational. A known synced control returned real timed lines. All library entries have a lyrics lookup date, and the snapshot contains no current enrichment errors. There is no persisted per-provider attempt history, so those fields cannot prove every historical Spotify call succeeded.

Among the 1,036 entries missing synced lyrics, 523 already had a saved Spotify ID. Repeating the existing Spotify lookup logic for all 1,036 produced 468 lyric-not-found responses, 56 plain-lyrics responses and 512 searches without a usable match. One previously unidentified entry matched during the fresh search. No extra timed lyrics appeared through the original lookup strategy. Five temporary HTTP 429 failures were retried and resolved as not found.

Changing only the lookup title and artist variants then produced 18 valid additional timed matches. The full YouTube Music title often includes both Japanese and Romanized or translated names. Searching just the native title can find a Spotify recording that the full bilingual string misses. Artist aliases matter too, especially the several spellings of Kishida Kyoudan and Sokoninaru already associated with the same YouTube artist channel.

The app only searches Spotify when there is no saved Spotify ID. It does not test alternate recording IDs after a lyric miss. Its matcher uses token overlap, which is a poor fit for combined Japanese and Romanized titles, and a duration difference cannot by itself disqualify a candidate. GraphQL errors and HTTP-200 error-shaped lyric responses can also collapse into a no-match result because the response checks do not distinguish them.

These findings point to matching and observability problems rather than a generally broken Spotify lyrics endpoint.

## LRCLIB misses

The current LRCLIB adapter has two concrete gaps:

- It returns immediately when `/get` supplies plain lyrics, so it never searches for a synced alternative. “Ether” by Ave Mujica demonstrated this during the audit.
- Its search takes the first duration-compatible result, even when another compatible result contains synced lyrics. It also makes one combined artist/title query, which misses native titles and artist aliases.

The broader audit searched all compatible candidates, preferred actual timed text and tried native-title variants. Artist aliases were constrained to the same known channel or independently verified names. Final acceptance required the same song title and a duration difference of at most three seconds, with recording version qualifiers preserved.

LRCLIB still has 29 unresolved entries after retries because searches returned service errors or timed out. Many have long video or cover titles. They remain unknown, not evidence of lyric absence.

[LRCLIB's server source](https://github.com/tranxuanthang/lrclib/blob/main/ARCHITECTURE.md) documents metadata lookup and search as separate paths. The app should keep the first plain result as a fallback while checking search for better timed results.

## Japanese websites and providers

PetitLyrics is the most useful new source found in this audit. Its public catalog distinguishes plain, line-synced and word-synced submissions. More usefully, its structured endpoint returned actual timed payloads for 156 recording-matched library entries. Word timings can be reduced to normal line-level LRC. Line-synced records require pairing a timing payload with text from the same lyrics ID.

This mechanism is unofficial and can change. [Canticle's provider implementation](https://github.com/sydlexius/canticle/blob/main/internal/petitlyrics/client.go) documents the request format and [its decoder](https://github.com/sydlexius/canticle/blob/main/internal/petitlyrics/decode.go) documents both payload types. The audit tested requests and decoded real timestamps locally; it did not rely only on a site's “synced” badge. Exact timing/text line counts and source IDs were checked. Trailing blank timed cues were retained when present in the payload.

Uta-Net has broad plain-text coverage for your artists. Comparing the public song catalogs for [Sokoninaru](https://www.uta-net.com/artist/19685/), [tricot](https://www.uta-net.com/artist/14790/) and [Kishida Kyoudan](https://www.uta-net.com/artist/10096/) found 92 missing-synced entries with matching lyrics pages. Of those, 69 currently have no lyrics at all and 23 have plain lyrics. These are text sources for a later alignment step, not confirmed timestamp sources. These counts overlap the API recoveries and should not be added to 187.

Sekaiphoria's current global and Japanese sitemaps each contained 787 song URLs. Strict artist/title slug matching found three library entries for [Sokoninaru's “相聞詩 / Soumonka”](https://sekaiphoria.com/lyrics/sokoninaru-soumonka-lyrics). The checked pages provide Japanese text, romanization and translation without timestamps. That song is already covered by the broader LRCLIB lookup. I would not prioritize Sekaiphoria for synced lyrics.

The AMLL TTML database was also checked against saved Spotify IDs. None of the missing-synced entries matched its Spotify-indexed files. That is only an ID-index check, not a claim that AMLL or NetEase cannot contain another matching recording. NetEase, QQ and other catalogs were not exhaustively audited.

## Recording versions need protection

There are 47 entries whose titles explicitly identify an instrumental recording. Thirty-nine lack synced lyrics. They were excluded from the recovery count, even when a vocal recording has almost the same duration.

Eight instrumental-labeled entries already have synced lyrics and one has plain lyrics. Five of the synced entries contain text and timings identical to a vocal version in the library. These are candidates for reviewing unwanted vocal lyrics on instrumental recordings, rather than automatically deleting their sidecars. The eight synced instrumental entries remain part of the reported stored coverage of 761.

Broader lookup without version checks produced 34 additional provider hits on instrumentals. Those results were rejected. In particular, splitting a title at every ` - ` can remove “Instrumental” and produce a convincing but wrong vocal match.

Protect instrumental, live, cover, TV-size, remix, demo, acoustic and new-recording qualifiers. A title match and nearly identical duration alone do not establish the same version. Treat lyric files for covers and concert uploads as needing alignment to the actual local audio.

## Turning plain lyrics into synced lyrics

There is no reliable text-only conversion. Timestamps must come from a timed source, manual timing or aligning the known words against the actual audio.

Of the 134 existing plain entries, 58 already have a matched timed source in this audit. One is labeled instrumental. That leaves 75 existing plain entries as candidates for generated timing, including 57 identified as Japanese. Other currently empty entries also have newly found text from API providers or Uta-Net, so the eventual alignment pool is larger.

I would pilot alignment on ten Japanese songs with clear vocals and good native-language lyrics before adding a batch feature. [lyric-align](https://github.com/ijuinryukichi/lyric-align) specifically supports CJK lyrics, sung vocals and LRC output, and can leave unmatched lines explicit. Whisper-based forced alignment is another option. Neither was run in this audit, so there is no measured timing accuracy for your audio yet.

The implementation can be small: run a separate local alignment process with the audio and Japanese text, validate the resulting LRC, then pass it through the existing tag/sidecar/upload steps. Keep generated timing identifiable and review failures. Use external timing tools for manual correction so this app remains a library builder.

## Recommended implementation order

1. Fix matching and quality preservation. Try native titles and artist aliases, retain recording qualifiers, prefer synced candidates, and preserve existing synced lyrics when a provider fails or only plain text returns. Do not overwrite good lyrics with a weaker result during an outage.
2. Add PetitLyrics as an optional fallback after the existing timed sources. It supplies 118 distinct recoveries beyond the 69 found through better Spotify and LRCLIB matching.
3. Add a lyrics-only refresh/backfill action. Reuse the established recording metadata and local audio; avoid sending the library through a general rematch or download cycle. Stage changed lyrics, update tags/sidecars and mirror them through the existing inventory workflow.
4. Record a small per-provider attempt result: lookup time, query, matched ID and outcome such as synced, plain, no match, not found or error. Retry errors sooner and negative results periodically. The existing last-checked date and error object do not explain why a provider was skipped or returned nothing.
5. Pilot audio alignment on the remaining plain Japanese entries. Add Uta-Net text lookup if the pilot works well and the added text yields useful timing results. Expand to more providers only after measuring the residual gaps.

Existing-source matching fixes plus PetitLyrics offer a tested availability gain of 187 entries. Alignment is the next experiment, with 75 existing plain entries available as input; its success rate remains to be measured.

- `existing-instrumental-lyrics.json`: the nine instrumental-labeled entries carrying lyrics.
- `rejected-candidates.json`: vocal results excluded from instrumental coverage.
- `file-verification.json`: embedded lyric validation for every audio file.
- `snapshot.db`: a consistent read-only audit snapshot.
- Lookup scripts, logs, API response captures and downloaded candidate LRC files.

Every one of the 1,036 missing-synced entries was considered by each provider audit. Spotify variants were only issued when useful variants were available, and the 39 missing instrumental entries were skipped for PetitLyrics. YouTube Music's unauthenticated adapter passed three known-synced controls but yielded no new timed matches. No generated alignment was performed. Exact title variants and verified artist aliases, a three-second duration tolerance, version checks and real nonzero timestamps underpin the accepted recovery count. The imports still deserve timing checks against the local recordings.
