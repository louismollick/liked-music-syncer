# Verify the Remote Library against upload records

Only the app writes to the Remote Library, so the app records the content hash and the full tag field set of every file it uploads. Routine checks compare rclone's size and modification-time listing with the upload records, each upload is followed by a hash check of that file, and a file without an upload record (after the database is rebuilt) is checked the same way, one object at a time. The app never requests a hashed listing of the whole remote, because SFTP servers compute those hashes by reading every file. Local files are compared against the upload record to find which fields differ. It does not run any program on the remote server and does not read remote tags in normal operation. When no upload record exists, or a remote hash matches no record, the app downloads that file and reads it locally. This works on any rclone backend and needs nothing installed on the server, at the cost of a slow full check after the database is lost.
